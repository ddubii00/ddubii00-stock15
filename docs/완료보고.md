# Telegram Reader 구현 결과

작성 기준: 2026-10-03 KST. **사용자가 Oracle 정상 운영을 확인했습니다. 이번 변경은 로컬 작업본과 GitHub 소스에 반영하며, 이 세션에서 Oracle 서버를 직접 업데이트하거나 실제 Telegram 계정을 연결하지 않았습니다.** 소스 저장소는 [ddubii00/ddubii00-stock15](https://github.com/ddubii00/ddubii00-stock15)입니다. 실제 비밀값을 요청하거나 파일에 기록하지 않았습니다.

배포 설정 정합성: 소스·venv 경로 `/var/www/stock15-7`, 운영 데이터 `/var/lib/stock15-7`, 서비스 `webapp-stock15-7.service`로 맞췄습니다. nginx는 Vite assets를 직접 제공하고 HTML/favicon/API만 8017로 전달합니다. 비밀번호 최소 4자를 유지했습니다. README의 최초 설치와 기존 서버 업데이트를 분리하고, 빌드 후 공개 파일 권한을 디렉터리 755/파일 644로 맞추도록 추가했습니다. 기존 서버 업데이트는 env·Telegram session·SQLite·운영 systemd/nginx 설정을 보존하며 웹 로그인만 재시작 후 다시 필요합니다. 배포 회귀 검사와 CI 검증을 추가했습니다.

추가 변경: X 클릭 즉시 숨김 및 실패 시 복원, 여러 대화방 표시 선택·해제, 최신 메시지를 먼저 보여주는 `시간순`과 이름으로 묶는 `대화방순`, `밝음`/`어두움` 전환. X 저장 성공 후에는 Telegram 피드를 재조회하지 않습니다. 백엔드 36개 및 프런트엔드 3개 테스트와 브라우저에서 지연 응답·연속 숨김·실패 복원·다중 필터·정렬·화면 밝기를 확인했습니다. 이 변경을 Oracle에서 사용하려면 프런트엔드 빌드와 백엔드 업데이트를 함께 적용해야 합니다.

1. **전체 architecture**: React/Vite/TypeScript → nginx HTTPS `/stock15-7/` → FastAPI → Telethon MTProto history + SQLite 메타데이터. Telemoa 공개 데이터는 별도 httpx adapter로 읽습니다. 유료 DB/SaaS/OpenAI API/AI 요약은 없습니다.

2. **생성/수정 파일**: `frontend/src/App.tsx`, `TelemoaPanel.tsx`, `api.ts`, `style.css`, 개발 전용 `demo.ts`; `backend/app/config.py`, `auth.py`, `db.py`, `telegram.py`, `feed.py`, `time_utils.py`, `telemoa.py`, `main.py`; `scripts/telegram_login.py`, `preview_external.py`, `security_check.py`; `deploy/webapp-stock15-7.service`, `nginx-telegram-reader.conf`; README, 빈 `.env.example`, `.gitignore`, Python requirements와 runtime lock, npm lock, backend/frontend 테스트, GitHub CI. production build는 `frontend/dist`에 생성되며 Git 대상에서 제외됩니다.

3. **SQLite schema**: selected_chats(chat_id, enabled, sort_order, created_at), hidden_messages(chat_id, message_id, hidden_at), app_settings(key, value), web_sessions(token_hash, csrf_token, expires_at). 본문/작성자/캡션/미디어 컬럼과 대화방 제목 저장 컬럼은 없습니다. 정확한 DDL은 README와 `backend/app/db.py`에 있습니다.

4. **Telegram API 사용 방식**: CLI만 인증코드 요청/sign_in을 실행합니다. 웹 서버는 기존 session으로 connect/is_user_authorized/iter_dialogs/iter_messages만 호출합니다. send/edit/delete/forward/read acknowledgement/join/leave API는 구현하지 않았습니다. entity 디스크 저장과 update 수신을 끄고, 조회 동시성 4개와 유한 재시도를 사용합니다. FloodWait는 429와 Retry-After로 알립니다.

5. **메시지 영구저장 금지 확인**: synthetic 본문을 실제 API 조회한 뒤 SQLite schema, SQL dump, 파일 bytes에서 본문/작성자 미저장을 검증했습니다. 브라우저 localStorage/sessionStorage/IndexedDB도 사용하지 않습니다. 미디어는 다운로드하지 않습니다. 모든 API와 정적 응답은 no-store이고 nginx는 cache 및 proxy buffering/temp-file 저장을 끕니다. 실제 Telegram 계정으로 검증한 결과라는 뜻은 아닙니다.

6. **X 숨김 동기화 방식**: (chat_id, message_id, hidden_at)만 SQLite에 기록하고 조회 시 batch ID 비교로 제외합니다. 두 독립 브라우저 cookie jar가 같은 선택·숨김 상태를 읽는 테스트를 통과했습니다. 열린 화면은 15초 간격 메타데이터 revision 확인과 window focus 확인으로 변경을 반영합니다. **기록삭제**는 확인창 후 웹앱 메타데이터와 웹 세션을 삭제하고 VACUUM하며, Telegram 인증 파일과 환경변수는 유지합니다. 모든 브라우저가 로그아웃됩니다.

7. **KST 날짜 처리**: ZoneInfo('Asia/Seoul')로 당일 00:00 이상, 다음 날 00:00 미만 범위를 만들고 UTC로 변환합니다. naive datetime은 거부합니다. 2026-10-02 15:01 UTC → 2026-10-03 00:01 KST, 2026-10-03 14:59 UTC → 23:59 KST, 정확한 자정 포함/다음 자정 제외 테스트를 통과했습니다. 숨김이 많은 방에서도 pagination이 전역 정렬을 유지하고 중복/누락 없이 전진하는 테스트를 통과했습니다.

8. **Oracle에 직접 넣을 secret 목록**: TELEGRAM_API_ID, TELEGRAM_API_HASH, TELEGRAM_PHONE, APP_PASSWORD. `/etc/stock15-7.env`에서 사용자가 직접 입력합니다. 인증코드와 Telegram 2FA password는 터미널 프롬프트에서만 입력하며 파일에 넣지 않습니다. Telegram session은 인증 후 서버에서 생성됩니다. APP_ORIGIN과 경로/TZ 변수도 README대로 설정합니다.

9. **최초 Telegram 인증 명령**:

   ```bash
   sudo systemd-run --collect --wait --pty \
     --uid=telegram-reader --gid=telegram-reader \
     --working-directory=/var/www/stock15-7 \
     --property=EnvironmentFile=/etc/stock15-7.env \
     --property=UMask=0077 \
     /var/www/stock15-7/.venv/bin/python scripts/telegram_login.py
   ```

   전용 사용자에게 환경변수가 이미 안전하게 주입된 터미널에서는 `python scripts/telegram_login.py`. Oracle 인증은 아직 실행하지 않았습니다.

10. **build/test 결과**: npm ci, Vite production build와 TypeScript 검사 성공. backend pytest **42개 통과**, frontend Vitest **3개 통과**. TestClient의 httpx 사용에 대한 upstream deprecation warning 1건이 있으나 테스트 실패는 없습니다. source security scan과 배포 정합성 검사 통과. 이전 UI 작업에서 개발용 demo 데이터의 production JS 미포함과 브라우저의 Telemoa 공개 목록·검색·정렬·X 숨김·기록삭제·데스크톱/모바일 화면을 검증했습니다. 이번 배포 설정 작업은 Oracle의 실제 systemd/nginx 설정이나 개인 Telegram 계정을 읽거나 변경하지 않았습니다. 실제 nginx 설정 문법은 서버에서 `sudo nginx -t`로 확인합니다.

11. **최초 설치용 Oracle systemd 명령**:

   ```bash
   sudo install -m 644 deploy/webapp-stock15-7.service /etc/systemd/system/webapp-stock15-7.service
   sudo systemctl daemon-reload
   sudo systemctl enable --now webapp-stock15-7.service
   sudo systemctl status webapp-stock15-7.service --no-pager
   sudo systemctl restart webapp-stock15-7.service
   ```

   root가 아닌 전용 telegram-reader 사용자, 127.0.0.1:8017, 1 worker로 실행합니다. 첫 설치 때 마지막 restart는 필요 없습니다. 이미 운영 중인 서버에는 위 install 명령을 실행하지 않고 [README의 기존 서버 업데이트 절차](../README.md#b-기존-oracle-서버-업데이트)를 사용합니다.

12. **nginx 설정**: 최초 설치 때 기존 HTTPS server 안에 `deploy/nginx-telegram-reader.conf`를 추가합니다. `location ^~ /stock15-7/assets/`는 `alias /var/www/stock15-7/frontend/dist/assets/;`로 JS/CSS를 직접 제공합니다. 나머지 `/stock15-7/`는 `proxy_pass http://127.0.0.1:8017/;`로 prefix를 제거하고 FastAPI root_path와 Vite base가 외부 prefix를 유지합니다. no-cache/no-buffering/access_log off. 설정 후 `sudo nginx -t`와 `sudo systemctl reload nginx`를 실행합니다. 일반 소스 업데이트에서는 현재 nginx all-stocks 설정을 덮어쓰지 않습니다.

13. **최종 접속 주소**: 현재 로컬 미리보기는 `http://127.0.0.1:5173/stock15-7/?demo=1`. Telegram 메시지는 모두 가상 예시이고 Telemoa 영역만 실제 공개 조회 데이터입니다. Oracle 운영 주소는 서버 APP_ORIGIN 뒤에 `/stock15-7/`를 붙인 주소이며, 이 세션에서는 실제 서버 접속을 검증하지 않았습니다. 제목/종목을 누르면 [Telemoa](https://telemoa.com/) 또는 블로그 원문으로 이동합니다.

14. **GitHub에 포함되지 않은 secret 파일 확인**: 실제 .env/session/sqlite 파일은 소스에 만들지 않았고, `.env.example`은 값 없이 이름만 있습니다. gitignore와 Git index 검사로 .env/.env.production/session/journal/sqlite/sidecar/data/secrets 제외를 확인했습니다. GitHub 관리 대상은 소스와 배포 안내·설정이며, Oracle의 인증정보와 운영 데이터는 제외합니다. 소스 압축파일에는 승인된 Git 소스만 들어가고 node_modules, dist, private 파일과 .git history는 제외됩니다.
